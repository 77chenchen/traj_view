# Trajectory and graph contract · v1

`schema/trajectory.schema.json` is generated from the Pydantic models and uses JSON Schema 2020-12. Canonical steps have unique, ascending nonnegative `idx` values. Indices can have gaps. Timestamps are original strings when provided. `raw_ref.line` is one-based for JSONL and nullable when no exact physical line is known.

`meta.raw_text` preserves the complete UTF-8 source. Adapters preserve unrecognized input there and may also expose it in structured metadata. `meta.final_message` is a normalized source final message when available. Use the `final_message` tag on its actionless step. Unspecified outcomes have label `unknown`. Preserve source labels and nullable pass status. A nonzero observation exit code indicates a process error even if the source omits the error flag.

## Build output

- `index.json` is `{schema_version: 1, phases, runs, search_file: "search.json"}`. Each phase is `{id, label, symbol, color}`. Each run summary is `{id, source_format, task_id, model, agent, condition, outcome, limits, usage, metrics, langutory, file, steps_file, canonical_file}`. Paths are relative to the index.
- `runs/<key>.json` contains `{id, expanded, aggregated}`. Each graph is `{nodes, edges}`. Expanded nodes are sorted by step order.
- `steps/<key>.json` contains `{steps: Step[]}`, loaded when a recorded-evidence view or Inspector needs it. `trajectories/<key>.json` contains the full canonical trajectory.
- `search.json` maps run IDs to searchable text. It is requested when a full-text search starts.
- Each node is `{id, label, signature, tool, category, phase, count, first_idx, step_indices, error, phase_counts}`. `signature` is the compact JSON string representation of `[normalizedTool, normalizedTarget]`. `tool` may be null for an actionless step. `category` is one of `shell, read, edit, validate, plan, tool, message`. `phase_counts` maps phase IDs to counts. Aggregated nodes use the first phase for color and preserve all member phases in `phase_counts`.
- Each edge is `{id, source, target, type, count}`, where `type` is `temporal, dependency, retry, structural`. Expanded edges point forward in source order. Aggregated edges roll up by ordered endpoints and type, including self-loops.
- Run metrics are `{steps, nodes, edges, aggregate_nodes, aggregate_edges, cycles, repeated_actions, error_rate, first_edit, first_validate, validated_after_last_edit, edit_validate_edit, phase_transitions, max_steps_hit, empty_termination, skill_read_steps, skill_read_count}`. `nodes` and `edges` refer to Expanded. `cycles` counts cyclic strongly connected components in Aggregated, including self-loops. Rates use the range 0–1. Missing first steps and validation with no prior edit are null. `phase_transitions` is a nested source-to-target count map. A max step limit is hit when observed step count reaches the supplied limit. Empty termination means the last step is actionless (or absent) and there is no final message.
- `langutory` joins phase symbols with a space in step order. `phase_source` is `rule` for rule-based labels (including `other`) and `llm` for an explicitly enabled model or cached model label.
- First divergence is the zero-based sequence offset of the first signature mismatch. Include both source indices and allow null on the shorter side. For identical sequences all divergence fields are null. Signature Jaccard is intersection size divided by union size, with value 1 for two empty sets. Compare ignores actionless steps for both measures.

Adapters expose `load(path: Path, source_format: str | None = None) -> list[Trajectory]` and `AdapterError` through `backend.adapters`. Graph code exposes `PhaseClassifier.from_file(path, llm_cache=None)`, `classifier.annotate(trajectory)`, `classifier.phases`, `langutory(trajectory, phases)`, `build_graphs(trajectory)` returning the run graph, and `compare(left, right)` through `backend.graph`. `backend.metrics.compute_metrics(trajectory, graphs)` computes the summary.

## Viewer behavior

Filters are OR within a field and AND across fields. Plain search is a case-insensitive substring over the run metadata and step thought, action, and observation text. Regex matches the Langutory string and reports invalid patterns. Run IDs are unique per build, independent of adapter. Duplicate input IDs are errors.

An expanded node represents exactly one canonical step. Both main views render Expanded as left-to-right DAGs. UI folding combines consecutive equal signatures into source-contiguous intervals and retains member indices; it is automatic at 2,000 steps and can be toggled for shorter repeated traces. Cross-block edges roll up by endpoints and type. Internal edges are omitted from the display DAG and retained in the member Inspector. Expansion restores the original step nodes and edges. Step filtering follows contraction and keeps an entire interval when at least one original member satisfies all filters; no filtering reconnects or synthesizes edges. Playback follows position in ascending step order, including when timestamps or indices are missing or nonconsecutive. The Inspector shows the raw file reference as well as canonical step content.

Normalize tool and category names to lowercase. For shell actions, use the effective command category and normalized file target when one is available. Shell validation signatures identify the operation, such as `validate:test` for pytest or unittest. Normalize slash direction and redundant path segments without reading the filesystem. Prefer explicit adapter targets and preserve the first occurrence order. Compare every unordered pair within a selected task. Cross-run selection matches a normalized signature across the expanded run DAGs, highlighting every occurrence while preserving separate nodes and positions. First-divergence markers compare each run to the first selected baseline, using the action-sequence offsets and exact left/right source indices defined above; an ended side has no node marker.

Sankey transitions use two time layers so reverse and self transitions can be rendered. A portable HTML report includes the same summaries, searchable content and lazy step payloads. Its embedded manifest points to separately parsed payloads. The viewer preserves source indices outside the safe JavaScript integer range as decimal strings internally. CSV emits one metric row per selected run (all runs from the CLI). Graph images include the visible edge types and nodes of the current view.

Recorded activity and file targets use the existing steps payload. Current-run stage previews preload this payload once; graph activity expansion reuses the cache. The file list uses only `action.targets` and explicit path-like argument keys (`target`, `targets`, `path`, `paths`, `file`, `files`, `file_path`, `filename`), normalized lexically. It records attempted targets, not verified reads or writes. Command-only paths and observation mentions are not added to this list. `Step.thought` can contain message or reasoning text; v1 has no distinct message role, reasoning channel, file-operation outcome, duration or call-parent fields. The UI reports absent content and timestamps as “Unrecorded / 未记录” (legacy detail blocks also use “None recorded”) and does not reconstruct missing information. The persisted v1 contract is unchanged; Aggregated remains available for signature frequencies, cyclic-group metrics and exports.


## Hierarchy and live views (no contract change)

Long single-run Overview is also a temporary projection of Expanded. At 60+ source steps it is the initial level: up to three contiguous content sections per level, then up to four original calls. A deterministic change-point tree uses recorded operation categories, command invocations, literal Python import lines and file subjects. Explicit `action.targets` take priority; simple path-like operands of read commands can also supply a subject, displayed with `cmd:` and a qualification in Section contents. Command operands never enter the confirmed-target list or establish a file access. The tree does not infer tasks. Nodes summarize operation counts, recorded subjects and errors; Section contents exposes the grouping basis and exact source examples. If the evidence has no strong content boundary, the view explicitly describes continuation batches for navigation. Nonadjacent repeats remain at their separate positions. Summaries preserve exact member indices and full-interval counts even when a filter matches only some members. Expansion replaces only the chosen frontier interval with its children in the same canvas. Other branches remain, and several nested or independent sections can stay open. Frontend-only `groups` enclosures hold a descriptive node, visible member IDs, parent and depth; they are not execution nodes, do not duplicate source steps, and add no execution edges. Clicking an enclosure header collapses that interval and its open descendants. Collapse last / Alt+↑ closes the most recently opened visible section; Collapse all restores the root frontier. Ordinary toggles preserve zoom and anchor the clicked card/header. Exact inspected source, URL and saved evidence survive collapse. Search adds the path to its exact source without closing unrelated branches. Only original inter-section edges roll up by endpoints/type/count; original internal and cross-range relations remain queryable from leaf Context. Filters never synthesize links. Global search, failure navigation and Context reveal the precise source node. Orthogonal execution routes account for section and call dimensions, keep x forward and avoid other nodes' interiors; category y-spacing does not assert concurrency. Long-run dependency focus hides unrelated dependencies until All dependency connections is enabled. No view metadata is persisted. See [inline behavior and verification](research/inline-graph.md) and [grouping rules](research/semantic-graph.md).

Hierarchy is a temporary frontend projection of Expanded. It uses `view`/`depth` only in React memory; neither field is persisted. Root groups cover contiguous phase spans or adjacent repetitions of tool-signature patterns with periods 1–8. Loop children are iterations, then original source calls. Each group preserves the exact source-index interval. Visible edges map to the most specific visible representative; internal self-edges are retained only in member details. Structural links mean containment, not proven execution causality. Filtering follows grouping, retaining a group when any source member matches; endpoints remain present and the result remains topologically sortable.

Live mode republishes the existing v1 dataset from completed Codex JSONL items, without adding timestamps, parent calls or dependency fields. In-progress tool items appear after their completion event. Source/provider termination and capture timeout counts are separate local capture metadata; an adapter's unknown outcome is not a benchmark pass. SSE status is a server API, not part of the frozen dataset schema.

## Replay and timeline projections

Replay reads the existing expanded graph and steps payload. Source selection persists by exact `idx` across Replay, DAG and Timeline. The Diff pane renders an explicitly recorded patch-like string from `action.args.patch`, `input`, `diff` or `action.command`; line numbers use explicit unified-diff hunk coordinates when supplied and excerpt ordinals otherwise; file coordinates are never reconstructed. Workspace shows `args.content` or a read-category observation. Neither is a complete filesystem snapshot. Observation preserves source truncation/error/exit flags. Latest-error evidence means the nearest earlier error in source order, not a proven root cause.

Timeline uses timestamp points only when all steps have parseable, nondecreasing timestamps and the first/last differ. All other cases use ordinal source-step position. Lanes are evidence categories, not agents or inferred concurrency; no call duration is synthesized. Personal notes live only in browser storage or explicit note JSON downloads and never change the v1 dataset. The legacy action-offset comparison remains available, preserving repeated occurrences. The primary A/B panel adds deterministic normalized-signature LCS alignment, bounded to 250,000 cells; above the limit it states its ordinal fallback. It does not infer semantic equivalence. Cost and subagent topology are unavailable in v1.


## Compact debug workbench projection

The shared navigation and Replay panes do not change v1 or introduce a new replay store. `idx` remains the single selection identity; ordinal slider position is translated through the original step array. Next failure/edit/validation controls navigate source evidence. They make no claim that one event caused a later result. Incompatible event filters clear when navigation would otherwise hide the selected row.

Diff highlighting is lexical and text-only; +/- markers decorate the original explicit patch. Tests displays only the selected validate-category step's observation; other steps show that test output is unrecorded. Cost remains unrecorded. Compare labels retry from incoming retry edges and differing output from recorded observation objects. The legacy offset rows and first-divergence calculation remain separate from primary LCS alignment. Neither matching method establishes causal equivalence. Missing observations remain distinct from reported exits.

Timeline's 1/2/5/10 tick intervals, lane gridlines, event centers and marker widths share a single scaled plot coordinate system. Label-column width stays fixed. Ordinal ticks have integer positions and display one-based step labels, independent of nonconsecutive or very large source indices. Marker width is visual scaling only, never call duration.

## Four-reference view projections

The shared shell and four-page compositions add no persisted fields. URL hashes store `view`, `run`, exact decimal `step`, and repeated `compare` run IDs. Stage snapshots preserve five/six evidence positions; absent roles retain explicit missing slots. Planning requires a plan-category action, otherwise generic text is Recorded Text. Test-failure wording requires a normalized test call; a non-test failure uses Tool/Recorded Failure or Validation Failed. Code Patch requires saved patch text; other edit-category records use File Edit. Re-run requires an earlier failed validation with the same normalized signature; a first validation is labeled Validation. Passed Tests requires a successful test-category validation; other successful validations say Validation Passed. These are source-backed evidence labels, not a count of execution phases.

Replay selects recorded patches, read/content excerpts or command/text output when the source changes. File Context identifies the nearest earlier read-category event with a shared explicit target and can jump to that source; this is a recorded excerpt, not a recovered filesystem version. The displayed delta is a timestamp gap between adjacent source steps, never a call duration. File target lists represent attempted targets; patch +/- counts count the saved patch lines.

Timeline uses six fixed evidence lanes. The Reasoning lane is visibly qualified as recorded text because v1 does not distinguish message and reasoning roles. Events can occupy multiple lanes (a tool call can include text and an edit); the lanes do not establish concurrency. Phase bands bridge source positions and are not tool durations. A final-message tag yields neutral Completion; green Validation Passed requires a validate-category record with exit code zero and no error. Activity groups by the run-level agent or evidence category, with active time and per-step agent identity unrecorded. Node attempt counts remain unrecorded; retry-link counts are separately labeled.

Compare metric bars/charts share a per-metric A/B scale. Tool calls count action-bearing steps; retry summaries count expanded retry-edge frequencies, not independently verified attempts. Tokens sum available input/output counters; missing usage is not zero. Cost and test pass rate are unavailable, even when a test output contains a pass summary. Unified Diff compares the latest recorded patch arguments; A/B Final files are shown only when complete content is explicitly recorded. Findings state source outcomes and computed quantities without claiming benchmark correctness.

The local `/api/report.html` endpoint downloads a single-file export of the active dataset. It has no schema effect; offline views use embedded payloads, issue no HTTP requests and do not need that endpoint.
