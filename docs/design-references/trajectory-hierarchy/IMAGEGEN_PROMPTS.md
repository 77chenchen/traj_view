## Graph

```text
Use case: ui-mockup. Redesign the attached desktop screenshot into ONE new, high-fidelity desktop application screenshot for the same product, "Agent Trajectory Viewer". 16:10 landscape, edge to edge application UI, no device frame, no web-browser tabs or address bar. The attached picture is the edit target and a source of the page's workflows. Rethink its visual hierarchy and greatly lower the density above the fold. Preserve its light enterprise workbench identity, purple accent and semantic green/red. Consistent design system across views: 54px top bar with a small stacked purple trace icon, "Agent Trajectory Viewer", light breadcrumb, and compact search; 174px white left rail, one thin right border, labeled line icons for Replay, Timeline, Graph, Compare, Analytics, Datasets, and a muted dataset line near the bottom. Selected nav item uses a light lavender fill. Main surface near white #FAFAFD with white working surfaces, slate ink #171C31, muted slate #58647B, accent #6345D6, light gray divider #E3E6EF. Use legible Inter-like text, 29px page title, 14px body, 12px secondary, sensible 8px spacing grid and 30px page margins. Use flat grouping, thin horizontal dividers and ample breathing space. Use restrained corner rounding for inputs, selected items, graph nodes and the single workspace surface. Prefer functional text; avoid decorative eyebrows, promotional copy, shadows, gradients, nested rounded cards and wall-to-wall boxed thumbnails. Make the screenshot look like an actual, precise shipped React desktop workbench, with crisp text and UI-aligned pixels. Keep text sparse and accurately spelled.

Page: Graph. Breadcrumb "Runs / run-8f3e9d2a / Graph". Active nav Graph. Main title "Execution graph". Immediately under title one understated inline metadata row: "run-8f3e9d2a · Fix failing authentication tests · 2m 14s" with a green "Success" indicator. A single unboxed thin phase strip "Plan   Investigate   Failed test   Patch   Re-run   Passed" shows "Patch" selected with a purple underline. Use about 62% of the main viewport for one wide, lightly dotted process canvas, starting directly below an unboxed tool row with "Layers" and "Fit" and subtle icons. It is by far the biggest element. Show a compact process diagram with two branches and a merge, sparse and easy to read, similar logic to reference: Plan → Investigate → Read files on upper branch; Plan → Edit code → Failed test → Retry on lower branch; both join before Passed. Short node labels only. Outline low-saturation blues/purple, subtle error red, completed green. Highlight "Edit code" with purple outline and softly tinted fill. Place small vertical + and − controls within the canvas. An open, slender "Step details" inspector on the right is separated by one vertical hairline and shows only selected evidence: "Edit code", "app/auth.py", tabs "Details   Diff   Output", and a short three-line red/green diff in a single code surface, with a discreet link "Open full diff". Its hierarchy stays subordinate to canvas. Below the canvas, add one low-emphasis collapsed row "Agent activity" with a chevron, conveying access to the old activity timeline. No phase preview cards, dashboard grids, or permanent inspector subsections. Give the canvas white space and keep left and right columns aligned.
```
