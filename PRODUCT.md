# TrajViz

TrajViz is a local analysis tool for people inspecting and comparing coding-agent traces. It normalizes recorded logs to frozen v1 datasets, provides source-ordered DAGs and metrics, and exports a standalone offline report. The operating goal is to understand tool calls, repeated loops, explicit file targets, failures and divergence between runs of the same task.

The primary investigation follows failure → command/output → recorded patch → later validation. A selection is a run ID plus the exact source `idx`; the same identity persists across Replay, Timeline, Graph, Compare and the shared URL. Display ordinals and action offsets remain distinct from source identity. Repeated normalized signatures retain every individual source occurrence.

Desktop reading uses 16px prose, 15px bundled JetBrains Mono evidence, 14px controls and smaller 13px directory/source metadata. Selected evidence leads at 18px. Muted Graph/Timeline category colors share a palette; selection, failure and diff remain separate meanings. The code font and its license travel with the standalone report. See the [reading and color verification](docs/research/readable-typography.md).

The current desktop direction uses white continuous workspaces, near-white supporting panes, open section edges, dark text and blue selection; green/red retain outcome meaning. Graph remains white with no dot pattern in both appearances. A 64px single-row GitHub-style topbar contains only the existing site mark and six icon/text tabs with an active underline. It stays in normal document flow and disappears when the document scrolls down. Graph, Timeline and Replay use single-screen desktop layouts with local evidence scrolling. Compare, Analytics and Datasets use document scrolling, independent workspace heights and generous section gaps. There is no left app rail, topbar product name/breadcrumb, global search field, help/notification button or avatar. Catalog search stays available with ⌘K/Ctrl+K; appearance and dataset information move to a catalog disclosure. See the [neutral vertical workspace](docs/research/neutral-vertical-workspace.md) and subsequent [Replay refinement](docs/research/replay-layout.md), with desktop evidence at 1586×912 and 1280×800. The requested generated transparent logo is explicitly deferred by the user; the existing monochrome mark stays in use.

Evidence boundaries are binding. The frozen v1 step contract has no separate message/reasoning role, per-step agent identity or call-parent, duration, attempt-count, full filesystem snapshot, cost or test-pass-rate fields. Native Codex rollout metadata can preserve source roles/channels, exact call/output references and their recorded interval in optional `meta.rollout`. Recording details shows these facts on demand; Source coverage exposes timestamp, phase-source and token coverage, saved messages and the full redacted source download. Recorded intervals include waits and do not establish active process runtime. Known complete single-literal wrappers can expose their submitted command or native patch without executing log text. Original wrappers remain available. Recorded text alone does not establish a reasoning role. Show absent information as Unrecorded / 未记录; a recorded zero remains zero. Adjacent timestamp gaps are not call durations. Only explicit targets/path arguments support file targeting, which does not itself prove successful modification.

Structural graph links mean containment. Dependency links retain the existing documented file/observation heuristics. Never infer agent hierarchy or parallel branches from a visual reference. Compare alignment uses normalized action signatures, with an original-action-offset fallback for large sequences; matching and rejoining do not establish semantic equivalence or success. First divergence retains its original zero-based action offset and each side's exact source index. Patch comparison uses the last saved patch arguments with source provenance; complete final-file content is shown only when explicitly recorded.

Preserve the schema, adapters, CLI and existing data/export contracts. Reference task names, sample metrics and sample code are never product data. Personal annotations stay separate from trace evidence. Private captures, logs and credentials stay in ignored local directories; public fixtures and screenshots use synthetic data.
