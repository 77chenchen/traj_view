# TrajViz

TrajViz is a local analysis tool for people inspecting and comparing coding-agent traces. It normalizes recorded logs to frozen v1 datasets, provides source-ordered DAGs and metrics, and exports a standalone offline report. The operating goal is to understand tool calls, repeated loops, explicit file targets, failures and divergence between runs of the same task.

The primary investigation follows failure → command/output → recorded patch → later validation. A selection is a run ID plus the exact source `idx`; the same identity persists across Replay, Timeline, Graph, Compare and the shared URL. Display ordinals and action offsets remain distinct from source identity. Repeated normalized signatures retain every individual source occurrence.

The current desktop direction uses pale continuous workspaces, near-white panels, blue-gray single-pixel boundaries, dark text, purple selection and green/red outcomes. Light is the default appearance; dark remains a saved local preference. Keep the existing product name, mark, shared topbar, six-item navigation and dataset controls. The latest three-page hierarchy is implemented and documented in [the direction and verification report](docs/research/three-page-hierarchy.md); its scope is desktop, with evidence at 1586×912 and 1280×800.

- **Graph:** the source DAG canvas leads beneath a compact stagebar. Layers, Legend and Agent activity are closed initially. The Inspector has an empty prompt until a node is selected, then reveals recorded detail, patch, output or context.
- **Compare:** one shared A/B alignment leads, supported by three flat metrics. Step comparison begins closed unless a source is provided by the route. Patch comparison, All metrics and Run DAGs are named alternative workspaces; Agent A details, Agent B details and Key Findings are separate closed disclosures. A is green and B purple. Two to four same-task runs remain supported in run DAG comparison.
- **Replay:** the source list supports the widest current-evidence area and a persistent transport. Step details begins closed. Saved patch/file/read, command output and recorded text remain available; secondary evidence and stage previews open on demand.

Timeline continues to show source-event distribution and a searchable event log. Analytics/Sankey, the dataset catalog and its filters, keyboard navigation, themes, CSV and graph PNG/SVG exports, live local refresh and single-file offline reading remain part of the product. Existing narrow-screen access remains supported; this revision does not establish a new mobile composition.

Evidence boundaries are binding. V1 does not separately record message/reasoning roles, per-step agent identity or call parents, call duration, attempt count, full filesystem snapshots, cost or test pass rate. Recorded text can appear in `thought`, but that does not establish a distinct reasoning role. Show absent information as Unrecorded / 未记录; a recorded zero remains zero. Adjacent timestamp gaps are not call durations. Only explicit targets/path arguments support file targeting, which does not itself prove successful modification.

Structural graph links mean containment. Dependency links retain the existing documented file/observation heuristics. Never infer agent hierarchy or parallel branches from a visual reference. Compare alignment uses normalized action signatures, with an original-action-offset fallback for large sequences; matching and rejoining do not establish semantic equivalence or success. First divergence retains its original zero-based action offset and each side's exact source index. Patch comparison uses the last saved patch arguments with source provenance; complete final-file content is shown only when explicitly recorded.

Preserve the schema, adapters, CLI and existing data/export contracts. Reference task names, sample metrics and sample code are never product data. Personal annotations stay separate from trace evidence. Private captures, logs and credentials stay in ignored local directories; public fixtures and screenshots use synthetic data.

[DESIGN.md](DESIGN.md) defines the current visual system; [the three-page references](docs/design-references/three-page-hierarchy/) define this desktop revision. The [earlier density work](docs/research/density-surface.md) and [dark four-page reference work](docs/research/four-reference-surface.md) remain historical records, not the current default direction.
